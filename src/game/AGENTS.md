# src/game rules
- Founding identity is derived in character.ts from equal-area terrain shares in a fixed radius-14 circle, excluding map edges; main and substantial secondary routes are labels only. Keep characterOf trade and charter behavior unchanged until explicit balancing, so identity display never alters population or earned money.

- Parchment silhouettes use the reusable figure-sized surface in parchment.ts and source-in tinting, never per-frame CSS filters on the world canvas; retain the existing VIP whitelist, depth clips and occlusion hysteresis to bound rendering cost without revealing ordinary residents.

- Replacement building art uses alpha-cropped WebP under sprites/cohesive with a 480-pixel longest edge; registry crop dimensions match real files and night layers share the same crop, preserving scale and aligned windows.

- Weddings: incremental calendar in src/game/weddings.ts (weddingDates: gap from care-capped residents, civic wealth and food crafts; dowry from wealth) mirrored exactly by DB village_weddings (used by village_balance and encounter_guard) — change both together. Couples/kin derived in people.ts marry()/kinOf, never stored. Village weddings gather everyone, give joy and call the mayor; in towns (care-capped era >= Kleinstadt) only every WED_NOTABLE-th is "grand" — the rest stay private (no banner, encounter or joy).
- Villager life (traits.ts, Sunday via isSunday() in time.ts, sickness/carers and wedding processions in people.ts) is derived from ids, homes and the clock; never store it — all clients see the same day.
- Disasters (src/game/disasters.ts): fires, floods and raids are a pure calendar from (seed id, time window) plus purchases; structureAt applies burning/rebuild/flood via tileHits, raid losses are mirrored by DB village_raids — never store disaster state, so all clients and the treasury agree.
- Timber build bonus: bought builds go up TIMBER_BUILD faster once sawmillUp (effAge past the sawmill landmark age) — pure, never tied to fluctuating larder stock so build times agree everywhere.
- Mentor bonus (mentorHours in world.ts) is derived from links + creation dates and added to effAge outside TRADE_CAP; never stored — late joiners catch up identically on every client.
- Journeymen and messengers between towns (src/game/wander.ts) are a pure calendar from road + UTC day; never stored — all clients see the same walkers.
- Family moves (wander.ts "family") empty a source house for VACANT_DAYS; derived, not stored.
- Neighbour gifts/aid/thanks: only gift rows are stored (DB gift_guard: prices, 1/day, treasury); carts (wander.giftWalkers), faster rebuild (Seed.aid → aidFactor) and balances are derived.
- Map zoom has one render path (no detail threshold): wild nature is placed by natureAt() in render.ts, baked into ground chunks only outside possible town reach — so trees, house facing and pastures never pop while zooming.
- Inaugurations (inauguration() in people.ts): villagers gather before a landmark for FETE_SECS after effAge passes its `at`; derived from clock, never stored.
- Personal space (src/game/space.ts): footprints + a pure separation pass at draw time (people vs. people/sheep, keep-right on roads); collisions are derived per frame, never stored — all clients agree.

- Calendar weights live in season.ts using UTC; season-art.ts caches alpha-preserving recolored images and nature/overview caches include the season key, so seasonal changes remain consistent without per-frame pixel processing.
- Goods hauling (Person.haul in people.ts) is derived from jobs and nearby buildings and animated as a pure clock cycle; never store goods or stock — all clients see the same carriers.
- Traffic and villagers use pure motion.ts headings and N-1 road segments to prevent facing flicker and overshoot.
- Animal routines in animals.ts use the realm clock; resting art and frozen dusk positions prevent nighttime motion.
- Landmarks relocate from their nominal offset to the nearest dry tile via landmarkSpots(seed) in world.ts (pure, cached) — so coastal/mountain towns never lose landmarks to water.
- Craft scenes (fisher casting, smith at anvil, mill sacks, bread basket) derive from the world clock in src/game/crafts.ts and job work sheets (JOB_WORK in folk-sprites.ts); props draw in the worker's mirrored frame so they always line up — nothing stored.
- Trade roads: every road touching a player village is a stored decision row (first_roads, DB guard: in reach, one row per direction, one under construction per village; either side suffices, build time from distance via roadHours (mirrored by DB road_done), a counter-decision halves the remaining time via roadDone); roadGate/roadCandidates/roadBuilding in world.ts derive links from them — sample-only pairs connect by themselves.
- Friend invites: only referral rows are stored (claim_referral DB function checks Weiler age, same map, new account, one per user); the 50-Taler bonus for both villages is derived via referralClaims in economy.ts and mirrored in village_balance.
- Grain storage is capped by grainCap(byKind) in goods.ts (base + per mill + per granary) and leftover grain feeds villagers as porridge; a second mill landmark appears as farming villages grow — all derived, never stored.
- Free game (src/game/wildlife.ts) lives in hashed dens on open nature map-wide; the nearest finished lodge hunts its deer dens in turn (huntTarget spacing > REGEN) and denFate empties/regrows them — pure from tiles + clock, never stored; figures are bucketed per tile in render pass 2.
- Guild ranks (Geselle/Meister) are purchase rows rank2/rank3 checked by the DB purchase_guard (age, guild building, belfry, finished roads); rank and bonuses are derived via rankOf/rankBoons in economy.ts — no separate rank state.
- Prestige monuments are defined once in MONUMENT_DEFS (world.ts: kind, step count) and MONUMENTS (economy.ts: stage, prices, bonuses); steps are purchase rows `<key><n>` checked by the DB purchase_guard and progress is derived via monumentProgress — add a monument there plus guard prices, never as a growth landmark.
- Player mayor steering (commandMayor/orderPose in people.ts) is local-only, never stored: other clients keep seeing the derived routine; the order expires ORDER_IDLE s after arrival.
- Mayor's seat: SEAT_KINDS landmarks share one reserved tile in LANDMARKS (world.ts) and swap by era (seat1 -> seat2 -> seat3 -> townhall); the mayor's home/work derive from it in people.ts — never stored.
- Mayor titles (Amt & Würden) are purchase rows title1..3 checked by the DB purchase_guard (charter, age, guild rank, previous title); title, bonuses and avatar insignia derive via titleOf/titleBoons/titleOfSeed in economy.ts — no separate title state.
- Stroll mode (driveMayor in people.ts): direct mayor steering is local-only like commandMayor, never stored; Game.tsx hides the HUD and the camera follows the mayor; leaving clears the steering.
- Encounters (encounters.ts): at most one open at a time — first after 3 min, then encounterGap(age) hours since the last decision (mirrored by DB encounter_guard); Game.tsx only offers it after the tab has been visible for 3 min, so encounters reward watching and never pile up.
- Rare saplings (cherry/quince): only the nursery encounter decision and the planting row are stored; owed saplings derive via saplingsOwed (encounters.ts), mirrored by DB sapling_guard; growth/season look is derived in drawRareTree (render.ts).
- Encounter scenes: visitors (guestNow), the maypole (maypoleUp), cows (cowsOf) and fire bucket crews are derived in townOf from decisions/fires + clock (Town.maypole/cows, Person.guest, fete.fire); never stored — so every parchment promise is visible identically on all clients.
- Care gate & emigration: careStage/careCeiling (world.ts) softly cap player towns below the next era until food/health crafts are bought; foodCapacity and occupiedHomes (households.ts) are the single roster for rendering and resident taxation — pure from bought rows, terrain and clock, sample towns exempt.

- Villagers (src/game/people.ts) are a pure function of seed, buildings and clock time; never store them — every client sees the same people. The renderer uses townPosesSmooth (exact poses every POSE_STEP ms, blended between) so big towns don't rerun every schedule per frame.
- Growth stages and water-adjacent landmarks are derived in world.ts; the world stays pre-industrial (no steam, no rails) so old and young towns share one era; retain sublinear expansion and core densification rather than saving progress, so offline growth remains reproducible.
- Twin towns: touch time (twinSince), pacts, joint works, gate sites and festival bonuses are derived in world.ts from seeds + twin_votes/twin_works rows (DB guard charges halves); never store twin state — all clients agree.
- Admin test map (realm "lab") reads its clock through clock() in src/game/time.ts, where LAB_SPEED warps time — keep LAB_SPEED at 1 (real time) unless the user asks for a time-lapse, because warping re-derives every town each second and costs performance; all game code must read time through clock(), never Date.now(), so any warp applies everywhere.
- Occlusion (render.ts): every standing thing — buildings, folk, animals, road crews, carts, traders, messengers, riders, stalls — is drawn in the per-tile depth pass (addProp/roadProp by toTile), never in a later overlay, so nothing ever rises above a roof in front. Ordinary folk and animals may simply vanish behind houses; only key figures (own strolling mayor, hovered/selected villager, robbers, messengers/riders) are re-drawn at the end as a faint sepia "parchment silhouette". Construction props (road works, site piles) sit on the open south verge so they stay visible.
- Taxpayers: economy.ts retains the historical pre-cutover estimate only; resident-tax.ts uses occupiedHomes and estateAt for new trusted daily receipts. Never switch only the HUD or accept client-supplied populations. No retroactive removal of earned money when activating the receipt ledger.
- Village chest (Gemeindetruhe): raids count in the chest ledger (taxes refill after robbers) and the balance is floored at 0; cappedTax/treasury in economy.ts walk settlement days and let tax (and post-cutover dowry) only fill the room below chestCap (base + purchase rows chest2..4); mirrored exactly by DB village_capped_tax/village_balance and guarded in purchase_guard — change both together; days before CHEST_SINCE stay uncapped so no balance is ever cut.
- Citizens (isCitizen/citizensOf in people.ts) are the only population count for HUD, roll and chronicle; the mayor avatar and travelling guests are drawn but never counted.
- Charter boons beyond tax/growth: culture lowers sickRate and new resident-tax receipts by CULTURE_SICK (prosperity.ts, never in legacy tax mirrored by DB); craft doubles disaster rebuild via craftRepair (disasters.ts) — pure from charter row.
- Settlement rank (rank.ts): the shown era, chronicle "stage" events and shop gating come from real state (citizens, occupied dwellings identified by Person.hh, finished roads) via townRank, never the clock; internal stageOf(effAge) only drives building style, and the shop uses min(rank, stageOf) so it never exceeds the DB purchase_guard.
- Trade roads stay 4-connected tile chains for logic (roadAt, bridges, traffic); visually they are drawn once per link as a smoothed ribbon (drawRoadRibbon in render.ts: averaged + Chaikin, frayed verges by hash) — never per-tile strokes, so stair steps never show.
- Trade networks: transitRoutes/hubRoutes in world.ts derive A–B–C trade from finished links (one middle town, TRANSIT_SHARE yield, TRANSIT_HUB for the hub) into effAge/speedParts; throughOn in wander.ts shows the matching carts/journeymen leg by leg with a hub rest — all derived, never stored.
- Character development: households.ts shares a radius-based food catchment across terrain and preserves richer legacy farms; density.ts adds real families inside eligible houses (staggered per character so none pulls ahead mid-game; plains only densify cottages/town houses), retaining legacy ground-floor families first. Floor-specific dwellingKey preserves old IDs and dwellingTile decodes kin destinations. Rendering, roll, rank and trusted residentTax share this roster; paid daily receipts and legacy balances never change retroactively.
- Food routes: farmers work fields, gardens and pastures; food-route.ts maps pasture labour with a bought dairy to cheese and garden labour to grain-equivalent meals. Existing field yields stay unchanged; do not store production or unlock care merely through terrain art.
- Character strengths are pure constants keyed by townCharacter (player towns only): STONE_FIRE in disasters.ts, GRAIN_WINTER in households.ts, GATEWAY_HUB via hubBonus in world.ts — none touch DB-mirrored rhythms (raids, weddings, roads), so client and trusted tax evaluator agree.
- Character landmarks: wayLandmark (world.ts) swaps the barn/warehouse landmark sites for dairy/fishery/granary/harbor by townCharacter — visual only, never homes, so taxes and rosters stay unchanged.
- Character house styles (HouseStyle in building-sprites.ts): hill (workshop) and coastal (gateway) towns redraw cottage/fachwerk/steinhaus/patrician with styled sprites keyed by townCharacter(seed).main; plains keep classic art. Purely visual — same width/base, own aligned night layer, households/tax/rank use the base kind.
- Way monuments (harvest/guildtower/lighthouse) are ordinary MONUMENTS entries with `way`; the build menu offers only the town character's one, the DB purchase_guard allows only one way monument per village (terrain is not computable in SQL) — keep prices and bonus totals equal across ways.
- Way complement: roads between towns of different main ways add WAY_COMPLEMENT to tradeFactor (world.ts, capped as before); way buildings send derived carriers in assignHauls (people.ts) — pure, so all clients and resident taxation agree.
- Trade soft cap (world.ts softTrade/tradeCapOf): trade counts fully to TRADE_CAP, then approaches the town ceiling (raised by gateway, trade charter, market hall); never below the old hard cap so existing towns never shrink. Surplus becomes toll prosperity in attributes() only — civic tax wealth/DB untouched.
- Wonders (src/game/wonders.ts): sites are a pure grid placement from terrain, mirrored 1:1 by DB wonder_sites (regenerate the INSERT if placement changes); only wonder_finds rows are stored via claim_wonder (same reward once per village – first finder per realm slightly more and honoured by name/days in the note, 3/day) and counted in village_balance/village_capped_tax.
- Prince's seat (src/game/court.ts): one estate site, layout and court routine derived purely from terrain + realm clock; canPlant blocks founding within COURT_GUARD — nothing stored, every client sees the same court.
- Mayor profile: seeds.mayor_age/mayor_traits are written only via the owner-checked update_mayor RPC; people.ts reads them (fallback: hashed age) and setChosenTraits overrides traitsOf, so all clients see the same mayor and sprite cohort.
- Audience (court.ts audienceHost/atCourt): host derived from realm hour, offered only to a strolling mayor on the estate; nothing stored until tasks exist.
- Princely decrees: only princely_tasks rows are stored, created/handed in solely via DB princely_audience (fixed 12-step sequence in princely_task_def mirrored by src/game/princely.ts, 20 h rest, conditions = rows newer than accepted_at, with stock fallbacks for finite road/build/wonder; princely_swap turns an open decree into "court" service once per 24 h, fulfilled by two on-estate errands (princely_errands rows via princely_errand; servants found with errandNear in court.ts); knighthood counts any 12 fulfilled); rewards enter village_balance/village_capped_tax at done_at — change both sides together.
- Knighthood: only knighthoods rows are stored (DB princely_knight: owner, 12 fulfilled decrees, once); the riding horse (KNIGHT_SPEED in people.ts, rider sprite for the own strolling mayor) is derived locally from that row.
- Supporter decorations (src/game/supporter.ts): only paid reward rows are stored (supporter_rewards, written solely by the signed payment webhook); placement around the mayor seat is derived via decorMap and never affects any game value.
- Speech bubbles (src/game/banter.ts + lang/banter.ts) are local-only and never stored; picks avoid the last 40 lines shown.
- Live strolling mayors of other players travel only over the ephemeral Realtime broadcast room mayors:<realm> (people.ts setRemoteMayor/remoteMayor, TTL fallback to the derived routine); never write positions to tables — keeps DB load zero.
- Village dog (supporter reward "dog", src/game/dog.ts): only the reward row and owner-chosen name (village_dogs) are stored; routine (romp, heel, night sleep by the seat) derives from clock + mayor pose, chase smoothing is local-only — purely cosmetic, never affects the game.
- Regional islands: realm → biome (biome.ts) sets tint/tree mix, and world.ts heightAt picks a per-biome outline and rivers (Europe/lab formula unchanged); ANCHORS lift founded villages to dry lowland and keep rivers away — add a village's coordinates there before ever changing a non-Europe formula. syncGeo resets terrain caches on realm switch; wonder sites of every realm must be mirrored in DB wonder_sites.
- In-game calendar: gameDate/gameYear in time.ts show the realm's real day with the year shifted by YEAR_SHIFT (2026 → 1500); display only, never used for growth.
- Per-tile ground detail (wild turf, field/garden/pasture furrows, plants, wattle, troughs) is drawn from cached variant sprites (turfSprite/agriSprite in render.ts); only textured base fills stay live because patterns are world-anchored. Ground chunks bake at most one per frame — keeps draw calls and panning spikes bounded.
- Flat town dressing (turf, paths, squares, acres) is baked per 16-tile chunk in render.ts (drawFlatChunks) with per-tile tokens checked in pass 1c; at most one ground-or-flat bake per frame, unbaked chunks fall back to live tiles — panning never waits. Figures, trees, sheep and plain houses use absolute setTransform instead of save()/restore() to keep the per-frame command count low.
- Figure anatomy (src/game/figure.ts): the shared leg cycle always keeps LEG_RATIO body height from the hip; hemY only sets how far the torso covers it, floor-length garments (prince, gowns) use drawRobeWalk; the dev Figure Lab (key P in dev or ?figs) draws every class through the same helpers, so guides match the game.
