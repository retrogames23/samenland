# src/game rules
- More src/game rules are split by size into src/components/AGENTS.md, src/game/lang/AGENTS.md, src/components/hud/AGENTS.md and src/assets/sprites/AGENTS.md.
- Founding identity is derived in character.ts from equal-area terrain shares in a fixed radius-14 circle, excluding map edges (gateway once river-weighted water+shore reaches GATEWAY_SHARE, since seeds always sit on land); main and substantial secondary routes are labels only. Keep characterOf trade and charter behavior unchanged until explicit balancing, so identity display never alters population or earned money.

- Parchment silhouettes use the reusable figure-sized surface in parchment.ts and source-in tinting, never per-frame CSS filters on the world canvas; retain the existing VIP whitelist, depth clips and occlusion hysteresis to bound rendering cost without revealing ordinary residents.

- Weddings: incremental calendar in src/game/weddings.ts (weddingDates: gap from care-capped residents, civic wealth and food crafts; dowry from wealth) mirrored exactly by DB village_weddings (used by village_balance and encounter_guard) — change both together. Couples/kin derived in people.ts marry()/kinOf, never stored. Village weddings gather everyone, give joy and call the mayor; in towns (care-capped era >= Kleinstadt) only every WED_NOTABLE-th is "grand" — the rest stay private (no banner, encounter or joy).
- Villager life (traits.ts, Sunday via isSunday() in time.ts, sickness/carers and wedding processions in people.ts) is derived from ids, homes and the clock; never store it — all clients see the same day.
- Disasters (src/game/disasters.ts): fires, floods (only river-bank tiles inside the town reach at flood time, never sea) and raids are a pure calendar from (seed id, time window) plus purchases; structureAt applies burning/rebuild/flood via tileHits, raid losses are mirrored by DB village_raids — never store disaster state, so all clients and the treasury agree.
- Timber build bonus: bought builds go up TIMBER_BUILD faster once sawmillUp (effAge past the sawmill landmark age) — pure, never tied to fluctuating larder stock so build times agree everywhere.
- Mentor bonus (mentorHours in world.ts) is derived from links + creation dates and added to effAge outside TRADE_CAP; never stored — late joiners catch up identically on every client.
- Journeymen and messengers between towns (src/game/wander.ts) are a pure calendar from road + UTC day; never stored — all clients see the same walkers.
- Family moves (wander.ts "family") empty a source house for VACANT_DAYS; derived, not stored.
- Daily limits (blessing, gifts, wonders 3/day, decree rest and swap) reset at the realm midnight: worldDayStart in time.ts mirrors DB realm_day_start — never rolling 24 h, so "come back tomorrow" is literal.
- Neighbour gifts/aid/thanks: only gift rows are stored (DB gift_guard: prices, 1/day, treasury); carts (wander.giftWalkers), faster rebuild (Seed.aid → aidFactor) and balances are derived.
- Map zoom has one render path (no detail threshold): wild nature is placed by natureAt() in render.ts, baked into ground chunks only outside possible town reach — so trees, house facing and pastures never pop while zooming.
- Inaugurations (inauguration() in people.ts): villagers gather before a landmark for FETE_SECS after effAge passes its `at`; derived from clock, never stored.
- Personal space (src/game/space.ts): footprints + a pure separation pass at draw time (people vs. people/sheep, keep-right on roads); collisions are derived per frame, never stored — all clients agree.

- Lying snow (snowCover in weather.ts, read via snowCoverAt in season.ts) is a snowpack depth walked over the past ten days of slots (snowStep: intensity × cold adds, warmth/rain/sun melt, dry frost keeps; tempAt gives per-winter severity and spells) and drives snow on ground, trees, roofs and ways (waySnow follows cover only, never the season alone); never stored, so all clients see the same snow.
- Calendar weights live in season.ts using UTC; season-art.ts caches alpha-preserving recolored images and nature/overview caches include the season key, so seasonal changes remain consistent without per-frame pixel processing.
- Goods hauling (Person.haul in people.ts) is derived from jobs and nearby buildings and animated as a pure clock cycle; never store goods or stock — all clients see the same carriers.
- Traffic and villagers use pure motion.ts headings and N-1 road segments to prevent facing flicker and overshoot.
- Animal routines in animals.ts use the realm clock; resting art and frozen dusk positions prevent nighttime motion.
- Landmarks relocate from their nominal offset to the nearest dry tile via landmarkSpots(seed) in world.ts (pure, cached) — so coastal/mountain towns never lose landmarks to water.
- Craft scenes (fisher casting, smith at anvil, mill sacks, bread basket) derive from the world clock in src/game/crafts.ts and job work sheets (JOB_WORK in folk-sprites.ts); props draw in the worker's mirrored frame so they always line up — nothing stored.
- Trade roads: every road touching a player village is a stored decision row (first_roads, DB guard: in reach, one row per direction, one under construction per village; either side suffices, build time from distance via roadHours (mirrored by DB road_done), a counter-decision halves the remaining time via roadDone); roadGate/roadCandidates/roadBuilding in world.ts derive links from them — sample-only pairs connect by themselves.
- Villager names: pools in src/game/names.ts (≥750 per sex, sized to a full Hansestadt); people.ts picks first names by hash with linear probing per town so none repeats while the pool lasts — derived, never stored.
- Feast figures (star singers, fools, Whitsun ox, St Martin, lantern walk) come from feast-walkers.ts + people.ts schedules, pure from town tiles and realm hour.
- Feast props (door greenery, egg baskets, masks, torches, Corpus Christi canopy) and feast banter (lang/banter-feast.ts) derive from feastOn + realm hour in render.ts/banter.ts; only the per-account overlay receipt (feast_reads, merged with localStorage) is stored.
- Hofstellen (world.ts barnOfYard): a roadside barn stays only beside a farmhouse and never next to another barn, otherwise it becomes a dwelling — decided at the lot's own birth age, so finished yards never flip; a farmhouse with a yard barn gets YARD_HAND extra resident in households.ts — only ever adds homes, so no town loses residents.
- Village paths (pathAt) and lots share the reach edge r + 0.5, so a tile is a path from the moment it enters reach and a finished house is never overrun; site progress is returned per call (BuildOut), never module state, so keptPaths cannot leak a foreign site into another tile.
- Organic house sites use the fixed HOUSE_BUILD phase (world.ts), never age-scaled buildTime: big towns slow by building less often, not by slower sites; landmarks keep buildTime.
- Admin control desk (lab-ctl.ts + hud/LabDesk.tsx): local localStorage overrides/triggers for weather, season, feast, wedding, fire, flood, raid; every getter returns null outside realm "lab", so public maps and DB mirrors are never touched.
- Map overflow: every time zone has a chain of maps (REALM_NEXT in time.ts: europe -> europe-2 -> europe-3, us-west -> us-west-2, us-east -> us-east-2, asia -> asia-2) on the parent clock, each with its own height function and biome in world.ts/biome.ts (north German flora around 1500 only); a newcomer without a village lands on the first map below REALM_FULL (openRealm, Game.tsx), mirrored by DB realm_full_guard — only existing homes, admin picks and FORCE_EUROPE win. New maps need wonder_sites rows and the DB timezone CASE strips the "-N" suffix.
- Display-only age: render.ts reads town radius via viewAge (world.ts, clock rounded to VIEW_AGE_STEP) so frames hit the effAge memo; mechanics, tax and rank always call exact effAge. townTiles skips tiles beyond townDist > radius+0.5 unless they are own bought sites, own twin sites or roads credited to the town (roadOwnerAt) — exact, keeps results identical.
- Overview town bitmaps (drawOverviewTown/overviewKey in render.ts) are display-only caches keyed by radius, step, resolution, purchases, season and a 30 s tick; bridge checks cull by roadBox and screen span before structureAt — never inputs to mechanics.
- Schaukasten gate: lens and card offer a diorama only for the kind painted on the map (paintedKind in inspect.ts via streetHouse), so street-repainted houses never open a mismatched room; townhouse/townhouse2 share the townhouse-room wide layout.
- Schaukasten (stube.ts + components/Stube.tsx): the farmhouse, hut and handwerker dioramas (one painted room per kind and town building style via townCharacter, same slot layout) plus the patrician tall cross-section (own 2:3 layout and storey slots via PATRICIAN_SLOTS incl. counting desk) place residents purely from poseOf (home and not visible = at home) into painted room slots; gestures use painted pose pairs (<fig>-base/-top/-b.webp: fixed lower body, upper body pose A/B, timed by poseMix) — never whole-sprite rotation; local only, nothing stored, no effect on mechanics.
- Pasture herds (animals.ts herdAt): cow vs sheep per pasture tile from terrain + tile hash; display only, never touches food/tax.
- Schaukasten anchors (stube.ts BODY_ANCHORS/FURNITURE, anchorBottom/anchorX): every new or changed diorama figure needs a body-contact anchor (seat/feet/bed) and every room picture needs furniture anchors (bench/stool/chair/floor/bed); figure positions are always derived from both — never free-estimated image positions or per-figure correction offsets. Dev overlay: ?anchors.
- Forest outline (forest-edge.ts forestShape) replaces the hard layer-6 contour in production via forestEdge() (lab-ctl.ts PROD_EDGE; localStorage "samenland:forest-edge"="off" falls back); display only, tree feet stay inside radius 0.72 and the fringe never touches water/sand/rock.
- Perf diagnostics: only perf-probe.ts (?perf=1; &perfdetail=1 adds fine spans, structureAt and draw-op counts; ?perf=0 = camera hook only; &bench=flat = real-device flat-cache zoom run; window.__flatState exact flat cache snapshot), baselines docs/perf, scripts scripts/perf — never affects normal play.
- Town quarters (workers', villa, mixed) are picked per 3x3 block hash in world.ts, never by compass angle — so coastline orientation cannot decide which quarter lands on dry ground.
- Economy simulation (src/game/simulation/) is offline only: imports real formulas, never imported by the live game; behaviour assumptions live only in profiles.ts.
- Watermill refuge (millRefuge in world.ts): when a finished bridge head takes the watermill's landmark tile, the mill is drawn on the nearest free shore tile instead — pure from seeds + clock, landmarkSpots unchanged so no other landmark moves.
- Village spokes (spokeDirs in world.ts): eight golden-angle headings per seed; only a spoke that meets water within SPOKE_PROBE tiles (rock never turns one, so mountain towns gain no extra reach) is turned to the open land heading farthest from the other spokes — pure from seed + terrain, never across water, so open-land towns keep identical roads.
- Spoke water bypass (spokeBends in world.ts): a spoke whose straight run meets water within BEND_REACH bends by the smallest turn that stays on buildable land and clear of other spokes; rock never bends one and unobstructed spokes keep their exact course — so flat and mountain towns stay identical.
- Monument group 1 effects count only physically finished steps (stepsDone/guildtowerDone in world.ts): belfry fire cut, Zunftturm build cut (never its own running step), Tanzhaus joy via festJoy in weddings.ts; belfry raid protection stays open because DB village_raid_list cannot compute build completion.
- Monument group 1 (belfry at finished steps: 1 fire duration ×0.90, 2 one fire tile less via n−1 with floor 1, 3 duration ×0.85 replacing 0.90 and total-loss threshold ×0.5, 4 completion only; random salts unchanged, dance house joy, guild tower build speed) acts only via stepsDone after physical completion; the belfry deliberately gives no raid protection because the DB raid mirror only sees purchase times — the town guard alone protects against raids.
- Erntedankhalle (way monument harvest) acts only via stepsDone: step 1 careFoodExtra (care gate only, guarded so the hall never counts during its own build chain — avoids sawmill/effAge recursion), step 2 winterHunger in goods.ts, step 3 sickChance winter half + floodFarm 0.6 for all farm produce (fields, gardens, pastures); HARVEST_GRAIN store bonus also stepsDone. No DB mirror needed: weddings keep their own FOOD list.
- Leuchtturm (way monument lighthouse) acts only via finished steps (lighthouseDone, guarded inside monumentChain so its own chain never reads its effects): step 1 winter fishing fishWinter 0.8 + one careFoodExtra, step 2 seaDist halves distance beyond MIN_SEED_DISTANCE on all roads of an own gateway town, step 3 LIGHTHOUSE_TRANSIT when s/via/to is coastal + LIGHTHOUSE_CEIL; no separate trade-factor bonus.
- Dom (cathedral, kind factory): effects only via cathedralDone (world.ts, guarded stepsDone); the Dom site is found via specialTile, never the first generic factory tile; Domspital nurses are the Dom priests after beguines (falls in people.ts) — keeps church, care gate and sickness deterministic without DB change.
- Universität: every effect reads universityDone (world.ts, finished steps only, uniBusy guard): 1 lecturers via specialTile slots in people.ts, 2 messengers ×UNIVERSITY_MESSENGER via uniChancery in wander.ts, 3 +1 in careHealthExtra, 4 PROSPER_MONUMENTS +2 civic works from step-4 completion + 6 h (deliberate); no sickness or journeyman effect. Legacy civicWealth PRESTIGE_BONUS.university4 (+15 prestige) deliberately stays payment + 6 h because DB village_civic_wealth mirrors it for legacy taxes and dowries — change only with a DB migration.

- Road reach: new decisions reach NEAR_ROAD_DIST (80), up to TRADE_DIST (120) only when fewer than two same-map towns lie within 80 or as counter-decision to a road the target already decided (roadReach/roadAllowed in world.ts, mirrored by DB first_road_guard; quest_guard keeps 120) — limits sprawl in dense areas; the synergy bonus keeps its BONUS_DIST (80) scale so existing roads never change. Sea ways (seaWays in world.ts: finished lighthouse step 1, smokehouse/saltquay, fisher's hut on water; max 2) count as roads in rankInput via roadsFor, and certifyRank stores them in rank_certificates.ways for the rank3 guard.

- Schütting (exchange): every effect reads schuettingDone (world.ts, guarded stepsDone) — step 2 two merchants + transitShare 0.80, step 3 tradeCapOf +EXCHANGE_CEIL (still ≤ TRADE_CEIL_MAX, only via softTrade), step 4 third merchant + 0.85; merchant slots come from exchangeMerchants in people.ts, never from SLOTS, so paying never acts early.
