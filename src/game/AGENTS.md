# src/game rules
- More src/game rules are split by size into src/components/AGENTS.md, src/game/lang/AGENTS.md, src/components/hud/AGENTS.md and src/assets/sprites/AGENTS.md.
- Founding identity is derived in character.ts from equal-area terrain shares in a fixed radius-14 circle, excluding map edges (gateway once river-weighted water+shore reaches GATEWAY_SHARE, since seeds always sit on land); main and substantial secondary routes are labels only. Keep characterOf trade and charter behavior unchanged until explicit balancing, so identity display never alters population or earned money.

- Parchment silhouettes use the reusable figure-sized surface in parchment.ts and source-in tinting, never per-frame CSS filters on the world canvas; retain the existing VIP whitelist, depth clips and occlusion hysteresis to bound rendering cost without revealing ordinary residents.

- Weddings: incremental calendar in src/game/weddings.ts (weddingDates: gap from care-capped residents, civic wealth and food crafts; dowry from wealth) mirrored exactly by DB village_weddings (used by village_balance and encounter_guard) — change both together. Couples/kin derived in people.ts marry()/kinOf, never stored. Village weddings gather everyone, give joy and call the mayor; in towns (care-capped era >= Kleinstadt) only every WED_NOTABLE-th is "grand" — the rest stay private (no banner, encounter or joy).
- Villager life (traits.ts, Sunday via isSunday() in time.ts, sickness/carers and wedding processions in people.ts) is derived from ids, homes and the clock; never store it — all clients see the same day.
- Disasters (src/game/disasters.ts): fires, floods (only river-bank tiles inside the town reach at flood time, never sea) and raids are a pure calendar from (seed id, time window) plus purchases; structureAt applies burning/rebuild/flood via tileHits, raid losses are mirrored by DB village_raids — never store disaster state, so all clients and the treasury agree.
- Timber build bonus: bought builds go up TIMBER_BUILD faster once sawmillUp (effAge past the sawmill landmark age) — pure, never tied to fluctuating larder stock so build times agree everywhere.
- Mentor bonus (mentorHours in world.ts) is derived from links + creation dates and added to effAge outside TRADE_CAP; never stored — late joiners catch up identically on every client.
- Journeymen and messengers between towns (src/game/wander.ts) are a pure calendar from road + UTC day; never stored — all clients see the same walkers.
- Family moves (wander.ts "family") empty a source house for VACANT_DAYS; derived, not stored.
- Daily limits (blessing, gifts, wonders 3/day, decree rest and swap) reset at the realm midnight: worldDayStart in time.ts mirrors DB realm_day_start — never rolling 24 h, so "come back tomorrow" is literal.
- Neighbour gifts/aid/thanks: only gift rows are stored (DB gift_guard: prices, 1/day, treasury); carts (wander.giftWalkers), faster rebuild (Seed.aid → aidFactor) and balances are derived.
- Map zoom has one render path (no detail threshold): wild nature is placed by natureAt() in render.ts, baked into ground chunks only outside possible town reach — so trees, house facing and pastures never pop while zooming.
- Inaugurations (inauguration() in people.ts): villagers gather before a landmark for FETE_SECS after effAge passes its `at`; derived from clock, never stored.
- Personal space (src/game/space.ts): footprints + a pure separation pass at draw time (people vs. people/sheep, keep-right on roads); collisions are derived per frame, never stored — all clients agree.

- Calendar weights live in season.ts using UTC; season-art.ts caches alpha-preserving recolored images and nature/overview caches include the season key, so seasonal changes remain consistent without per-frame pixel processing.
- Goods hauling (Person.haul in people.ts) is derived from jobs and nearby buildings and animated as a pure clock cycle; never store goods or stock — all clients see the same carriers.
- Traffic and villagers use pure motion.ts headings and N-1 road segments to prevent facing flicker and overshoot.
- Animal routines in animals.ts use the realm clock; resting art and frozen dusk positions prevent nighttime motion.
- Landmarks relocate from their nominal offset to the nearest dry tile via landmarkSpots(seed) in world.ts (pure, cached) — so coastal/mountain towns never lose landmarks to water.
- Craft scenes (fisher casting, smith at anvil, mill sacks, bread basket) derive from the world clock in src/game/crafts.ts and job work sheets (JOB_WORK in folk-sprites.ts); props draw in the worker's mirrored frame so they always line up — nothing stored.
- Trade roads: every road touching a player village is a stored decision row (first_roads, DB guard: in reach, one row per direction, one under construction per village; either side suffices, build time from distance via roadHours (mirrored by DB road_done), a counter-decision halves the remaining time via roadDone); roadGate/roadCandidates/roadBuilding in world.ts derive links from them — sample-only pairs connect by themselves.
- Villager names: pools in src/game/names.ts (≥750 per sex, sized to a full Hansestadt); people.ts picks first names by hash with linear probing per town so none repeats while the pool lasts — derived, never stored.
- Feast figures (star singers, fools, Whitsun ox, St Martin, lantern walk) come from feast-walkers.ts + people.ts schedules, pure from town tiles and realm hour.
- Feast props (door greenery, egg baskets, masks, torches, Corpus Christi canopy) and feast banter (lang/banter-feast.ts) derive from feastOn + realm hour in render.ts/banter.ts; only the per-account overlay receipt (feast_reads, merged with localStorage) is stored.
- Hofstellen (world.ts barnOfYard): a roadside barn stays only beside a farmhouse and never next to another barn, otherwise it becomes a dwelling; a farmhouse with a yard barn gets YARD_HAND extra resident in households.ts — only ever adds homes, so no town loses residents.
- Organic house sites use the fixed HOUSE_BUILD phase (world.ts), never age-scaled buildTime: big towns slow by building less often, not by slower sites; landmarks keep buildTime.
- Admin control desk (lab-ctl.ts + hud/LabDesk.tsx): local localStorage overrides/triggers for weather, feast, wedding, fire, flood, raid; every getter returns null outside realm "lab", so public maps and DB mirrors are never touched.
- Map overflow: realm europe-2 (Elbwerder) shares Altenland's flora (biome elbe, LOOK null) with its own heightElbe; uninvited newcomers without a village land there once europe holds EUROPE_FULL seeds (time.ts, checked in Game.tsx) — invites and existing homes always win.
- Display-only age: render.ts reads town radius via viewAge (world.ts, clock rounded to VIEW_AGE_STEP) so frames hit the effAge memo; mechanics, tax and rank always call exact effAge. townTiles skips tiles beyond townDist > radius+0.5 unless they are own bought sites, own twin sites or roads credited to the town (roadOwnerAt) — exact, keeps results identical.
- Overview town bitmaps (drawOverviewTown/overviewKey in render.ts) are display-only caches keyed by radius, step, resolution, purchases, season and a 30 s tick; bridge checks cull by roadBox and screen span before structureAt — never inputs to mechanics.
- Schaukasten (stube.ts + components/Stube.tsx): the farmhouse, hut and handwerker dioramas (one painted room per kind and town building style via townCharacter, same slot layout) place residents purely from poseOf (home and not visible = at home) into painted room slots; gestures use painted pose pairs (<fig>-base/-top/-b.webp: fixed lower body, upper body pose A/B, timed by poseMix) — never whole-sprite rotation; local only, nothing stored, no effect on mechanics.
- Pasture herds (animals.ts herdAt): cow vs sheep per pasture tile from terrain + tile hash; display only, never touches food/tax.
