# src/game/lang rules (plus src/game rules part 3: taxes, rank, trade, character)
- Speech bubbles (src/game/banter.ts + lang/banter.ts) are local-only and never stored; picks avoid the last 40 lines shown.
- Mayor tasks are presented as villager petitions or growth milestones via src/game/lang/petitions.ts (presentation only); quest keys, order, rewards and the DB quest guard stay unchanged so existing claims remain valid.
- Village chest (Gemeindetruhe): raids count in the chest ledger (taxes refill after robbers) and the balance is floored at 0; cappedTax/treasury in economy.ts walk settlement days and let tax (and post-cutover dowry) only fill the room below chestCap (base + purchase rows chest2..4); mirrored exactly by DB village_capped_tax/village_balance and guarded in purchase_guard — change both together; days before CHEST_SINCE stay uncapped so no balance is ever cut.
- Citizens (isCitizen/citizensOf in people.ts) are the only population count for HUD, roll and chronicle; the mayor avatar and travelling guests are drawn but never counted.
- Charter boons beyond tax/growth: culture lowers sickRate and new resident-tax receipts by CULTURE_SICK (prosperity.ts, never in legacy tax mirrored by DB); craft doubles disaster rebuild via craftRepair (disasters.ts) — pure from charter row.
- Settlement rank (rank.ts): the shown era, chronicle "stage" events and shop gating come from real state (citizens, occupied dwellings identified by Person.hh, finished roads) via townRank, never the clock; internal stageOf(effAge) only drives building style, and the shop uses min(rank, stageOf) so it never exceeds the DB purchase_guard.
- Trade roads stay 4-connected tile chains for logic (roadAt, bridges, traffic); visually they are drawn once per link as a smoothed ribbon (drawRoadRibbon in render.ts: averaged + Chaikin, frayed verges by hash) — never per-tile strokes, so stair steps never show.
- Trade networks: transitRoutes/hubRoutes in world.ts derive A–B–C trade from finished links (one middle town, TRANSIT_SHARE yield, TRANSIT_HUB for the hub) into effAge/speedParts; throughOn in wander.ts shows the matching carts/journeymen leg by leg with a hub rest — all derived, never stored.
- Character development: households.ts shares a radius-based food catchment across terrain and preserves richer legacy farms; density.ts adds real families inside eligible houses (staggered per character so none pulls ahead mid-game; plains only densify cottages/town houses), retaining legacy ground-floor families first. Floor-specific dwellingKey preserves old IDs and dwellingTile decodes kin destinations. Rendering, roll, rank and trusted residentTax share this roster; paid daily receipts and legacy balances never change retroactively.
- Food routes: farmers work fields, gardens and pastures; food-route.ts maps pasture labour with a bought dairy to cheese and garden labour to grain-equivalent meals. Existing field yields stay unchanged; do not store production or unlock care merely through terrain art.
- Character strengths are pure constants keyed by townCharacter (player towns only): STONE_FIRE in disasters.ts, GRAIN_WINTER in households.ts, GATEWAY_HUB via hubBonus in world.ts — none touch DB-mirrored rhythms (raids, weddings, roads), so client and trusted tax evaluator agree.
- Character landmarks: wayLandmark (world.ts) swaps the barn/warehouse landmark sites for dairy/fishery/granary/harbor by townCharacter — visual only, never homes, so taxes and rosters stay unchanged.
- Character house styles (HouseStyle in building-sprites.ts): hill (workshop) and coastal (gateway) towns redraw cottage/fachwerk/steinhaus/patrician/hut/handwerker/farmhouse/barn with styled sprites keyed by townCharacter(seed).main; plains keep classic art. Purely visual — same width/base, own aligned night layer, households/tax/rank use the base kind.
- Way monuments (harvest/guildtower/lighthouse) are ordinary MONUMENTS entries with `way`; the build menu offers only the town character's one, the DB purchase_guard allows only one way monument per village (terrain is not computable in SQL) — keep prices and bonus totals equal across ways.
- Way complement: roads between towns of different main ways add WAY_COMPLEMENT to tradeFactor (world.ts, capped as before); way buildings send derived carriers in assignHauls (people.ts) — pure, so all clients and resident taxation agree.
- Trade soft cap (world.ts softTrade/tradeCapOf): trade counts fully to TRADE_CAP, then approaches the town ceiling (raised by gateway, trade charter, market hall); never below the old hard cap so existing towns never shrink. Surplus becomes toll prosperity in attributes() only — civic tax wealth/DB untouched.
