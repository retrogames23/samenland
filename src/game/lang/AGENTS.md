# src/game/lang rules (plus src/game rules part 3: taxes, rank, trade, character)
- Speech bubbles (src/game/banter.ts + lang/banter.ts) are local-only and never stored; picks avoid the last 40 lines shown.
- Mayor tasks are presented as villager petitions or growth milestones via src/game/lang/petitions.ts (presentation only); quest keys, order, rewards and the DB quest guard stay unchanged so existing claims remain valid.
- Village chest (Gemeindetruhe): until CAP_ALL_SINCE the legacy formula (legacyTreasury / DB village_balance_legacy: day-capped tax, once-capped dowry, other income uncapped) stays unchanged; from CAP_ALL_SINCE every booking is walked chronologically (walkChest / DB village_balance_walk: credits fill only the room below the cap valid at that moment, surplus is lost, debits free room, raids floor at 0; same-time order tax, dowry, credit, debit, raid, key) — change TS and SQL together, never clamp only the end balance.
- Citizens (isCitizen/citizensOf in people.ts) are the only population count for HUD, roll and chronicle; the mayor avatar and travelling guests are drawn but never counted.
- Charter boons beyond tax/growth: culture lowers sickRate and new resident-tax receipts by CULTURE_SICK (prosperity.ts, never in legacy tax mirrored by DB); craft doubles disaster rebuild via craftRepair (disasters.ts) — pure from charter row.
- Settlement rank (rank.ts): the shown era, chronicle "stage" events and shop gating come from real state (citizens, occupied dwellings identified by Person.hh, finished roads) via townRank, never the clock; internal stageOf(effAge) only drives building style, rank milestone quests (hamlet/village/town/merchant/metro) use townRank alone — elapsed time is never a rank criterion; the shop uses townRank alone; before a rank-gated purchase the trusted server recounts the rank (certifyRank in treasury.server.ts → rank_certificates, 15 min), and the DB purchase_guard checks that certificate against item/monument stages instead of founding age — keep ITEM_RANK/MONUMENTS stages and the guard's need_rank equal.
- Trade roads stay 4-connected tile chains for logic (roadAt, bridges, traffic); visually they are drawn once per link as a smoothed ribbon (drawRoadRibbon in render.ts: averaged + Chaikin, frayed verges by hash) — never per-tile strokes, so stair steps never show.
- Trade networks: transitRoutes/hubRoutes in world.ts derive A–B–C trade from finished links (one middle town, TRANSIT_SHARE yield, TRANSIT_HUB for the hub) into effAge/speedParts; throughOn in wander.ts shows the matching carts/journeymen leg by leg with a hub rest — all derived, never stored.
- Character development: households.ts shares a radius-based food catchment across terrain and preserves richer legacy farms; density.ts adds real families inside eligible houses (shared radius rule 18/30; way rules only add: workshop stone/craft houses earlier, gateway merchant houses/tenements a 4th family from radius 30), retaining legacy ground-floor families first. Floor-specific dwellingKey preserves old IDs and dwellingTile decodes kin destinations. Rendering, roll, rank and trusted residentTax share this roster; paid daily receipts and legacy balances never change retroactively.
- Food routes: farmers work fields, gardens and pastures; food-route.ts maps pasture labour with a bought dairy to cheese and garden labour to grain-equivalent meals. Existing field yields stay unchanged; do not store production or unlock care merely through terrain art.
- Character strengths are pure constants keyed by townCharacter (player towns only): STONE_FIRE in disasters.ts, GATEWAY_HUB via hubBonus in world.ts — none touch DB-mirrored rhythms (raids, weddings, roads), so client and trusted tax evaluator agree.
- Character landmarks: wayLandmark (world.ts) swaps the barn/warehouse landmark sites for dairy/fishery/granary/harbor by townCharacter — visual only, never homes, so taxes and rosters stay unchanged.
- Character house styles (HouseStyle in building-sprites.ts): hill (workshop) and coastal (gateway) towns redraw cottage/fachwerk/steinhaus/villa/patrician/hut/handwerker/farmhouse/barn with styled sprites keyed by townCharacter(seed).main; plains keep classic art. Purely visual — same width/base, own aligned night layer, households/tax/rank use the base kind.
- Way monuments (harvest/guildtower/lighthouse) are ordinary MONUMENTS entries with `way`; the build menu offers only the town character's one, the DB purchase_guard allows only one way monument per village (terrain is not computable in SQL) — keep prices and bonus totals equal across ways.
- Way complement: roads between towns of different main ways add WAY_COMPLEMENT to tradeFactor (world.ts, capped as before); way buildings send derived carriers in assignHauls (people.ts) — pure, so all clients and resident taxation agree.
- Trade soft cap (world.ts softTrade/tradeCapOf): trade counts fully to TRADE_CAP, then approaches the town ceiling (raised by gateway, trade charter, market hall); never below the old hard cap so existing towns never shrink. Surplus becomes toll prosperity in attributes() only — civic tax wealth/DB untouched.
- Mayor address (lang/address.ts addressMayor/mayorWord/titleForm) derives from mayor_gender + townRank (town words from TOWN_ADDRESS_RANK) and is applied only at display; never stored, lines about other heads (Unser/fremde/andere) stay as written.
- Population/rank quests pay only against a fresh server rank certificate (rank + citizens, DB quest_guard); the client certifies first, so rewards cannot be forged.
- Wohlstand (prosperity.ts prosperityAt) is the single prosperity value: continuous from real citizens plus civic works and all ten standing monuments (PROSPER_MONUMENTS; attributes() computes no side wealth) bought by then (school weighted, never a switch); sharesAt turns it into estate shares for resident tax (taxSharesAt), villagers (estateSharesLive via citizen hook), house paint (setEstateHook) and the HUD (attributes().wealth) — so citizen, house, tax and display never diverge. civicWealth stays only as the DB-mirrored legacy/dowry input.
- Rank inputs (rankInput) and residentTax count citizens/dwellings straight from the householdsOf roster, never via townOf — same numbers as the citizen list, without rebuilding the whole town each assessed day.
