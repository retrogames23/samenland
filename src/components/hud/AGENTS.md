# src/game rules (part 4: wonders, court, supporters)
- Wonders (src/game/wonders.ts): sites are a pure grid placement from terrain, mirrored 1:1 by DB wonder_sites (regenerate the INSERT if placement changes); only wonder_finds rows are stored via claim_wonder (same reward once per village – first finder per realm slightly more and honoured by name/days in the note, 3/day) and counted in village_balance/village_capped_tax.
- Prince's seat (src/game/court.ts): one estate site, layout and court routine derived purely from terrain + realm clock; canPlant blocks founding within COURT_GUARD — nothing stored, every client sees the same court.
- Mayor profile: seeds.mayor_age/mayor_traits are written only via the owner-checked update_mayor RPC; people.ts reads them (fallback: hashed age) and setChosenTraits overrides traitsOf, so all clients see the same mayor and sprite cohort.
- Audience (court.ts audienceHost/atCourt): host derived from realm hour, offered only to a strolling mayor on the estate; nothing stored until tasks exist.
- Princely decrees: only princely_tasks rows are stored, created/handed in solely via DB princely_audience (fixed 12-step sequence in princely_task_def mirrored by src/game/princely.ts, 20 h rest, conditions = rows newer than accepted_at, with stock fallbacks for finite road/build/wonder; princely_swap turns an open decree into "court" service once per 24 h, fulfilled by two on-estate errands (princely_errands rows via princely_errand; servants found with errandNear in court.ts); knighthood counts any 12 fulfilled); rewards enter village_balance/village_capped_tax at done_at — change both sides together.
- Knighthood: only knighthoods rows are stored (DB princely_knight: owner, 12 fulfilled decrees, once); the riding horse (KNIGHT_SPEED in people.ts, rider sprite for the own strolling mayor) is derived locally from that row.
- Supporter decorations (src/game/supporter.ts): only paid reward rows are stored (supporter_rewards, written solely by the signed payment webhook); placement around the mayor seat is derived via decorMap and never affects any game value.
- Live strolling mayors of other players travel only over the ephemeral Realtime broadcast room mayors:<realm> (people.ts setRemoteMayor/remoteMayor, TTL fallback to the derived routine); never write positions to tables — keeps DB load zero.
- Village dog (supporter reward "dog", src/game/dog.ts): only the reward row and owner-chosen name (village_dogs) are stored; routine (romp, heel, night sleep by the seat) derives from clock + mayor pose, chase smoothing is local-only — purely cosmetic, never affects the game.
