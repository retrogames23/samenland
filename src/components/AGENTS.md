# src/game rules (part 2: economy mirrors, mayor, encounters, care gate)
- Friend invites: only referral rows are stored (claim_referral DB function checks Weiler age, same map, new account, one per user); the 50-Taler bonus for both villages is derived via referralClaims in economy.ts and mirrored in village_balance.
- Grain storage is capped by grainCap(byKind) in goods.ts (base + per mill + per granary) and leftover grain feeds villagers as porridge; a second mill landmark appears as farming villages grow — all derived, never stored.
- Free game (src/game/wildlife.ts) lives in hashed dens on open nature map-wide; the nearest finished lodge hunts its deer dens in turn (huntTarget spacing > REGEN) and denFate empties/regrows them — pure from tiles + clock, never stored; figures are bucketed per tile in render pass 2.
- Guild ranks (Geselle/Meister) are purchase rows rank2/rank3 checked by the DB purchase_guard (certified townRank via RANK_STAGE/need_rank, guild building, belfry, finished roads — never founding age; chest2..4 likewise via CHEST_STAGE); a player town's seat inauguration and chronicle entry fire on the real rank rise (seatFete in people.ts), not on landmark hours; rank and bonuses are derived via rankOf/rankBoons in economy.ts — no separate rank state.
- Prestige monuments are defined once in MONUMENT_DEFS (world.ts: kind, step count) and MONUMENTS (economy.ts: rank, prices, bonuses); steps are purchase rows `<key><n>` checked by the DB purchase_guard (order + once, no wait) and progress is derived via monumentProgress, which builds paid steps one after another so paying never advances the site — add a monument there plus guard prices, never as a growth landmark.
- Player mayor steering (commandMayor/orderPose in people.ts) is local-only, never stored: other clients keep seeing the derived routine; the order expires ORDER_IDLE s after arrival.
- Mayor's seat: SEAT_KINDS landmarks share one reserved tile in LANDMARKS (world.ts) and swap by era (seat1 -> seat2 -> seat3 -> townhall); for player towns render.ts repaints the finished seat by townRank (seatKindForRank in rank.ts, paint-only — jobs/homes keep the growth kind); the mayor's home/work derive from it in people.ts — never stored.
- Mayor titles (Amt & Würden) are purchase rows title1..3 checked by the DB purchase_guard (charter, certified townRank via TITLE_STAGE/need_rank, guild rank, previous title — never founding age); title, bonuses and avatar insignia derive via titleOf/titleBoons/titleOfSeed in economy.ts — no separate title state.
- Stroll mode (driveMayor in people.ts): direct mayor steering is local-only like commandMayor, never stored; Game.tsx hides the HUD and the camera follows the mayor; leaving clears the steering.
- Encounters (encounters.ts): at most one open at a time — first after 3 min, then encounterGap(age) hours since the last decision (mirrored by DB encounter_guard); Game.tsx only offers it after the tab has been visible for 3 min, so encounters reward watching and never pile up. Which visitor comes is a weighted pseudo-random draw (eventOf: hash of seed id + count; base weight, MIN_ERA, season multiplier, last EVENT_COOLDOWN blocked), context anchored at the window start so an open encounter never changes; the DB guard checks only gap and price.
- Rare saplings (cherry/quince): only the nursery encounter decision and the planting row are stored; owed saplings derive via saplingsOwed (encounters.ts), mirrored by DB sapling_guard; growth/season look is derived in drawRareTree (render.ts).
- Encounter scenes: visitors (guestNow), the maypole (maypoleUp), cows (cowsOf) and fire bucket crews are derived in townOf from decisions/fires + clock (Town.maypole/cows, Person.guest, fete.fire); never stored — so every parchment promise is visible identically on all clients.
- Care gate food list (CARE_FOOD world.ts, households.ts) counts markethall and guildhall as food so inland towns reach Metropole. Money-bearing lists (TAX_FOOD economy.ts, weddings.ts FOOD) must match DB village_tax_pop/village_weddings exactly (fisher,hunter,granary,dairy) — otherwise the shown balance exceeds what the server books.
- Care gate & emigration: careStage/careCeiling (world.ts) softly cap player towns below the next era until food/health crafts are bought; foodCapacity and occupiedHomes (households.ts) are the single roster for rendering and resident taxation — pure from bought rows, terrain and clock, sample towns exempt.

- Villagers (src/game/people.ts) are a pure function of seed, buildings and clock time; never store them — every client sees the same people. The renderer uses townPosesSmooth (exact poses every POSE_STEP ms, blended between) so big towns don't rerun every schedule per frame.
- Growth stages and water-adjacent landmarks are derived in world.ts; the world stays pre-industrial (no steam, no rails) so old and young towns share one era; retain sublinear expansion and core densification rather than saving progress, so offline growth remains reproducible.
- Twin towns: touch time (twinSince), pacts, joint works, gate sites and festival bonuses are derived in world.ts from seeds + twin_votes/twin_works rows (DB guard charges halves); never store twin state — all clients agree.
- Admin test map (realm "lab") reads its clock through clock() in src/game/time.ts, where LAB_SPEED warps time — keep LAB_SPEED at 1 (real time) unless the user asks for a time-lapse, because warping re-derives every town each second and costs performance; all game code must read time through clock(), never Date.now(), so any warp applies everywhere.
- Taxpayers: economy.ts retains the historical pre-cutover estimate only; resident-tax.ts uses occupiedHomes and estateAt for new trusted daily receipts. Never switch only the HUD or accept client-supplied populations. No retroactive removal of earned money when activating the receipt ledger.
- Historical news 1500/1501 (HISTORY in encounters.ts: werber/weser/sund/ablass): real-calendar UTC windows (game year = real − YEAR_SHIFT), once per village from 24 h, ahead of commons in pendingAll, excluded from the visitor draw; guests appear on the square via GUESTS. DB encounter_guard mirrors prices and windows — change both together.
- Finished-building letters (build-mail route) decide via buildMailDue in game/build-mail.ts: monuments are mailed once, on their last step, at monumentDone — never per step.
