## Grundsatz: Jede Ausgabe muss einen spielmechanischen Gegenwert haben
Jede Aktion, Investition, Begegnungsentscheidung oder sonstige Spielerentscheidung, die Mark kostet, muss einen konkreten, tatsächlich wirksamen spielmechanischen Nutzen bieten.

* Der angekündigte Effekt muss im Spiel tatsächlich eintreten.
* Der Nutzen muss für den Spieler nachvollziehbar und seiner Ausgabe angemessen sein.
* Kostenpflichtige Optionen dürfen nicht wirkungslos sein oder lediglich einen nicht vorhandenen Effekt versprechen.
* Eine kostenpflichtige Option darf nicht durch eine kostenlose, ansonsten gleichwertige Option vollständig entwertet werden.
* Rein erzählerische Entscheidungen ohne spielmechanischen Nutzen müssen kostenlos sein.

Das gilt für alle Spielsysteme: Gebäude, Monumente, Begegnungen, Sonderaktionen, Erweiterungen und künftige Funktionen.

Leitfrage vor jeder kostenpflichtigen Funktion: Warum sollte ein Spieler dafür Mark ausgeben, und welchen konkreten spielmechanischen Vorteil erhält er dafür?

## Samenland game
- Settlement street order is paint-only in street-layout.ts and the render depth pass; never feed its substitute house kind into simulation or taxation, preserving every existing household, job and balance.
- Identity/density rules: src/game/AGENTS.md; legacy trade unchanged.
- Civic estates and tax assessments are derived in prosperity.ts from historical purchases and charter, mirrored by database village_civic_wealth/village_estate_tax; temporary stock bonuses do not permanently promote residents, and homeKind preserves population when sprites upgrade.
- Occupied households are shared through game/households.ts; resident-tax.ts assesses those households on the trusted server, and immutable daily tax receipts are economic records, never stored growth. Keep legacy earnings before the cutover unchanged to protect already-spent balances.
- Agricultural household capacity treats fields, gardens and pastures equally in households.ts, shared by rendering and trusted resident taxation; seasons/care stay independent of farming art and farmland never counts below farmFloor(radius), so no founding terrain feeds fewer households than flat land.
- Town growth is a pure deterministic function of seed position + created_at (src/game/world.ts); never store growth state — every client computes the same town from the shared seed rows, so towns grow even when nobody watches.
- Rendering uses a devicePixelRatio canvas (capped at 2 on touch devices for mobile GPU load); preload compressed building sprites with per-kind sizes and ground anchors, using the same assets at every zoom level to avoid style changes while loading.
- Seed ownership is enforced in the database (seeds.user_id UNIQUE + RLS on auth.uid()); UI strings live in src/game/i18n.ts (de/en), game logic returns codes not text.
- Trade roads, synergy and twin towns are derived from seed pairs in src/game/world.ts (links/effAge); growth uses effective age, never stored state — keeps all clients identical.
- World, trade and population caches include seed positions and creation timestamps, so replacing equal-sized seed sets cannot reuse stale geometry or progression.
- Construction sites are derived, not stored: a building's site phase is the buildTime() window before its birth age (Structure.build); builders/woodcutters/masons are assigned in people.ts from that — keeps every client identical.

- Dorfsegen: blessings table with a 24h DB trigger cooldown; blessing timestamps are merged into Seed.blessed client-side and effAge adds the bonus purely — keeps growth deterministic across clients.
- Signposts sit on derived road tiles (signTile in world.ts); only the message is stored.
- Bought buildings are placed by specialSites(seed) in world.ts from purchase rows merged into Seed.bought; newcomers (Person.arrive) derive from bornAt() — both pure, so all clients agree.

- Building night lighting uses aligned, light-only sprite layers with the daylight sprite dimensions and anchors; schedules and flicker live in night.ts so windows stay aligned at every zoom without replacing daytime art.
- Encounters: the open encounter is derived in src/game/encounters.ts/commons.ts (pendingAll); only the chosen answer is stored, with prices, gap and windows enforced by the database guard. Answers are booked only by the trusted server (decideEncounter → bookEncounter recomputes the open encounter via encounter-verify.ts, ±120 s; town-life questions get a rank certificate) — never let the client insert encounters, so drawn events and their money or growth stay tamper-proof.
- Ratsbuch (M1 Paket 2b): from RATSBUCH_SINCE (encounters.ts, mirrored by DB ratsbuch_since(), far future until Paket 4) the six growth visitors leave the lottery (EVENT_KEYS_RB) and come as ratsbuch_requests (one per village and UTC day, max 4 open, none while 6 boons are active at the day's start), created lazily by ratsbuch_refresh under the village lock — no cron. An accepted request is an encounters row with request_id (same price and boonHours, outside gap, draw count and commons rhythm); encounter_guard enforces open/own/matching requests and the shared limit of 6 growth boons (active_boons at clock_timestamp(), so parallel bookings count). Requests are answered only via ratsbuch.functions.ts — never by the client.
- Day/night, villager routines, lights and bell use one world clock (src/game/time.ts, Europe/Berlin); never read the client's local hour, so all players see the same scene.
- Four realms (seeds.realm: us-west/us-east/europe/asia) are separate maps, each with its own shared clock in src/game/time.ts; players land by browser UTC offset, only admins (user_roles) may override — keeps day/night shared within a map.
- Villagers, waymarks, border banners/stones and construction props are painted sprites (src/game/folk-sprites.ts); banner cloth is tinted per town hue at runtime and drawn in world space so night lighting applies — no flat vector figures next to painted art.
- Coastal towns grow in town-space distance (townDist/landShape in world.ts): landward tiles are compressed by a land-share stretch so harbour towns fan inland; bounding boxes must use reachOf(s, r).
- Village chronicle (src/game/chronicle.ts) is derived from seeds between last visit (localStorage) and now; while the owner watches, Game.tsx diffs it periodically for illustrated celebrations — no stored history. Only the scribe greeting uses AI (authenticated server function, fixed fallback).
- Subdirectories have their own AGENTS.md (src/game/AGENTS.md) – read it before changing files there.
- Village stocks (src/game/goods.ts larderOf/storedAt/chainOf) are derived from jobs, season, clock and floods; never store goods — all clients see the same larder.
- Wood and stone (Wirtschaft Paket 1, src/game/resources.ts ↔ migration 0142) are the exception: a stored, append-only resource_ledger (start, daily production, Kontor, consumption) whose sum is the stock, booked only by the database under the village row lock (resource_book, resource_refresh lazily per UTC day without cron, purchase_material/purchase_material_book for bought buildings and upgrades: wood price/20, stone price/30 from 500 Mark; a missing amount is bought at the Kontor only up to the client's kontor_max). Active from resources_since(realm) — lab now, public maps only from a later migration; the client only displays resource_overview and quotes the Kontor price. The derived larder in goods.ts stays derived.
- Steingrube and location (Wirtschaft Paket 2, migration 0143): the Steingrube is a purchase row outside ITEMS (no civic work, so prosperity/tax/dowries never move), sold by the patched purchase_guard only where resources run, at most one per village, for 150 Mark and 20 wood (no grant or credit; the 0143 guard expression 300 − 150 is exactly that price). Since migration 0144 it is a visible building (SPECIAL_KIND steingrube → kind "quarry") placed in the normal build preview under the general rules only (reach, buildable, free tile; no geology), with a short site phase QUARRY_BUILD via specialDone(…, kind); no jobs, homes, prosperity or tax, not burnable, not movable (move_price lacks it). Rows bought before 0144 without a position are placed last by specialSites (oldQuarrySpot: just outside the village's own effAgeBound reach at purchase time + QUARRY_MARGIN) as an auto site, and structureAt shows such a site only where nothing else claims the tile (neighbours, roads and later growth win) — it never displaces or overwrites anything, so it may be hidden next to partner villages. Production still counts from the purchase. Production uses the village's location in village_sites (grain/workshop/gateway from townCharacter, certified once and final by the trusted server via certifyMySite; production days wait for it): woodcamp +4/+6/+3 wood, Steingrube +3/+4/+1 stone on top of 1 wood and 0.5 stone; the coast pays 90 % at the Kontor (resource_kontor), no surcharges. Keep SITE_* in resources.ts and the SQL equal.
- A1 investment material (migration 0145): monument steps, guild ranks and titles use wood price/40 and stone price/60 from 500 Mark (INVESTMENT_ITEMS/investmentNeed in resources.ts ↔ the a1 list in purchase_material); chests stay material-free. Same Kontor, kontor_max and booking as buildings; their buy buttons check price + kontorOf and show MaterialLine. Keep both lists equal (resources.test.ts).
- „2 aus 5“ (src/game/gemeinwesen.ts): Badestube and Beginenhof count as Gemeinwesen next to herb hut, healer and library, but only up to two (gemeinwesenCount); the classic count is never lowered. One rule for the care gate (careStage/careMissing, wedStage mirror) and the household capacity behind resident tax; legacy taxPop (before CAP_ALL_SINCE) stays frozen. Counted only from twoOfFiveSince(realm) — lab from 2026-11-25, public maps not before a release change — so nothing in the past is recomputed.
- Tavern chat (chat_messages/chat_blocks) is the only free-text player table besides signposts; length, rate limit and blocking are enforced by the chat_guard DB trigger, RLS limits letters to sender/recipient. Read marks per channel live in owner-only chat_reads (merged with localStorage by max), because preview frames and other devices lose browser storage.
- Neighbourhood: Saturday markets (stalls, traders, +growth) are derived from roads and the realm clock in wander.ts/world.ts; letters store only metadata publicly (riders/arrival derived from distance) while bodies sit in a sender/recipient-only table written via the send_letter function — every client sees the same riders, only the pair reads the text.
- Brand art: src/assets/logo-keimling.png is the logo; public/favicon.png is a downscaled src/assets/logo-icon.png.
- Gift dismissal receipts live in recipient-only public.gift_reads and are merged before displaying gift overlays, with an account-scoped browser fallback; this prevents read thank-you letters replaying across browsers and map reloads.
- Inactivity: user_activity.last_active_at is touched on every visit (touch_activity RPC); the daily /api/public/idle-sweep warns after 90 days and purges village+account (purge_user_data) 7 days later — admins exempt.
- Kummerkasten: bug_reports rows + private bug-shots bucket (user-id folder) are written by the player; the daily /api/public/bug-digest sends one digest with 7-day signed image links and marks rows sent — no other read path, so reports stay private.
- Mobile bottom HUD (rail, drawers, banners, walk stick) anchors only to the --dock-bottom CSS token in styles.css, never to raw env(safe-area-inset-bottom) — iOS Safari's floating toolbar is not in the safe area, so one token keeps every bottom element clear of it.
- Touch targets use the `hit` utility (styles.css: invisible ::after ≥44px on coarse pointers) and HUD edges use --safe-l/--safe-r; the tavern pins itself to visualViewport via direct style writes, never React state — keeps icons delicate and typing render-free.
- Input mode (coarse) follows the last PointerEvent.pointerType, seeded by the (pointer: coarse) media query, so hybrid iPads swap joystick/cursor live; the HUD uses logical start/end or ltr:/rtl: variants while the world and minimap canvases stay dir="ltr", so RTL never shifts world coordinates.
- Keyboard: one window listener in the canvas effect skips form fields; pan keys stay in KEYMAP, all other keys go to the per-render hotkey ref (Escape closes windows → modes → stroll) and Space glides via the glide ref inside panStep — no stale closures, no second listener.
- Camera zoom limits live in src/game/camera.ts and apply to every realm and input path; wheel, pinch, buttons, double-tap and stroll exit all use maxZoom so their limits cannot diverge.
- Church feasts (src/game/feasts.ts) are derived from the realm calendar (Julian Easter of the game year, snapped to the map's Sunday); rest days, bonfires, Whitsun tree, Christmas lights and the feast parchment all read feastOn() — never stored, so every player on a map keeps the same feast.
- Split Game.tsx into src/components/hooks/ (e.g. useTreasurySync) without behaviour change; the monolith is hard to maintain.
- Relocating bought buildings (Umsetzen): only building_moves rows are stored (DB building_move_guard: price by size, 7-day cooldown, one at a time, treasury); specialSites overlays moves after the original placement (old spot until the move, new spot rebuilt from it) and the trusted tax server ignores moves — so no auto-placed site shifts and paid receipts never change.
- Testebene 3 (src/game/simulation/*.test.ts) is excluded from `npm test` and runs only via vitest.sim.config.ts (test:sim*, test:all) — the 730-day runs far exceed the regular suite budget.
- Browser storage read at module scope must be wrapped in try/catch, never only a `typeof localStorage !== "undefined"` check: server contexts (SSR, workerd) expose a localStorage global whose access throws NotSupportedError, which took down every rank-gated purchase via the certification server function.
